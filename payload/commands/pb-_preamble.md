# Product Bench shared preamble

Run before every `pb-*` workflow.

1. Read `.product-bench-install.json` at the repository root to find `brain_dir`. Read that folder's `config.json`, `OPERATING-SYSTEM.md`, and `sources.json`. If setup has not filled the relevant context, say so before producing analysis.
2. Run `node <brain_dir>/runtime/product-bench.mjs doctor --target .`. If managed files are missing or changed, surface the result. Do not silently replace local edits.
3. Read only the command's `context_deps`. For each file, parse `Last updated:`. A missing file or `never` blocks claims that depend on it. A date older than `freshness_days` is stale; name the gap. A successful source fetch alone does not make content current.
4. Read `context/command-learnings.md` for a rule matching the current command. Apply only a specific rule with an observable trigger.
5. Check `config.json` routing prerequisites. For a hard prerequisite, find a matching artifact or ask for the already completed equivalent; do not infer that it exists. Soft prerequisites produce a warning.
6. Check enabled source capabilities. If an MCP or other source is unavailable, say `unchecked` and continue only with sources that actually worked. Never imply that data was fetched when it was not.
7. Context is shared in the repository. Review proposed facts before writing. Read only approved source scopes. Do not write raw transcripts, credentials, personal contacts, or customer datasets to context summaries.
8. Load the shared writing rules from `<brain_dir>/runtime/payload/brain/VOICE.md` and the team's `context/brand-voice.md`. Apply them throughout drafting and the final edit, including spoken scripts. If team voice is unfilled, use the shared defaults and name any missing brand-specific choices. Do not treat style guidance as evidence for a product claim. The runtime copy supplies current shared defaults after updates; preserve the team's reviewed brand file.
9. When the task includes model judgment, generated recommendations, or probabilistic quality, check for a matching eval design. If absent, use `/pb-evals design` to propose failure classes, human labels, thresholds, and a dataset plan before calling the build contract ready. Drafting can proceed with explicit gaps; deterministic acceptance criteria, AI quality evals, and business success metrics remain separate.

Run routine checks silently. Put material freshness, evidence, or tool gaps before the artifact; don't print a boilerplate checklist when there are no gaps. Read supplied task artifacts and their cited evidence in addition to declared company context, within approved source scope. Product Bench bundles SEO, decision-interview, readability, and document/deck skills for both hosts. Content Engine, Blog and Editorial Draft come together from the optional Content Engine import; resolve them through doctor.integrations.content and `<brain_dir>/runtime/payload/brain/EDITORIAL-DRAFT.md`. A missing optional import leaves its delegated phases pending and does not mean the bundled installation is broken. Read each invoked skill's actual instructions and resources; an absent bundled skill means an incomplete installation. External data providers, render runtimes, CRM access, and upstream engines still require actual availability. Skill installation does not prove a provider or tool ran. Follow the command's dependency contract and report incomplete capabilities honestly.
